# Cueward 0.5.0

This release collects the merged changes since 0.3.2. Versions 0.4.x are skipped. The published packages are `cueward-core`, `cueward-adapter-macos` and `cueward-cli`; the executable remains `cueward`.

## Main changes

- Scoped file browsing, bounded reads, filename/metadata search, Spotlight content search, native resource metadata, previews, Finder context and explicit iCloud download requests.
- Guarded file/directory creation, copy and duplicate, existing-tag edits, same/cross-volume relocation, bounded recursive/package copying and independent batch rename.
- Confirmed ordinary-file trash with retained verified backups, plus non-overwriting restoration from completed receipts' backups.
- Application discovery/background launch, window/AX inspection and actions, bounded waits, snapshot comparison, Space observation/creation and guarded window movement.
- Safari and CLI module splits, background-input lifecycle guards, optional AX-attribute compatibility fixes and expanded agent instructions.

See the [file operations guide](../files.md), [agent installation guide](../agent-skill.md) and [computer-use progress](../computer-use-progress.md) for detailed commands and evidence.

## Compatibility and limits

- Rust 1.88 or newer is required. Existing let-chain syntax already required 1.88; the old 1.85 declaration was inaccurate.
- The CLI remains macOS-only. `cueward-adapter-windows` is an unpublished stub, not Windows support.
- The 0.5 minor-series boundary does not promise source, CLI or JSON compatibility with 0.3.x. Recheck installed help and saved target/receipt consumers before upgrading.
- Filesystem scopes, version guards, explicit confirmations, non-overwrite behavior and recorded incomplete outcomes remain mandatory. No automatic replay, permanent deletion or general recovery is added.
- Provider/TCC behavior, older macOS compatibility and app-specific input acceptance retain the documented verification gaps.
- Locked-session operation is not supported or certified by this release. Retained-resource lock research remains a development tool, with actual lock/unlock phases unverified.
- Generic background canvas input, complete physical-input isolation and inactive-Space first-save behavior remain unresolved or unverified. Research fixtures are not generic app support.

## Release checks

On macOS arm64, the workspace release build passed with Rust 1.88.0. The complete source-checkout suite passed with 916 tests and 33 existing ignored tests using `cargo +1.88.0 test --locked -- --test-threads=1` under a disposable home directory. Default parallel execution encountered six receipt-test failures consistent with existing Notes/doctor tests mutating process-global `HOME`; serialization avoids that test-harness race, not a product repair.

All three publishable crates passed `cargo publish --workspace --dry-run --locked --allow-dirty`, including builds from their packaged contents. The dirty-worktree flag was only for preparation, not actual upload. Embedded adapter helper resources were included. CLI integration tests reference two sibling adapter fixtures and are run from the repository, not the standalone crate archive.

## Install or upgrade

After 0.5.0 is published:

```sh
cargo install cueward-cli --version 0.5.0 --locked
cueward --help
```

Updating an installed agent skill does not update the executable. Follow the synchronization guide separately; preserve local skill edits with verified backups.
