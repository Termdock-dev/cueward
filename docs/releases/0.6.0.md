# Cueward 0.6.0

This release makes background clicks work on views that ignore a first click. The published packages are `cueward-core`, `cueward-adapter-macos` and `cueward-cli`.

## Main changes

- `window click` and `window drag` now prepare the target. Cueward tells only the target app it is active, clicks the title bar once, sends the action and restores the app. Ordinary web pages and views that refuse first mouse now receive the click. See [click preparation](../background-input.md#click-preparation).
- Results of clicks and drags report `pointer_preparation`: `title_bar_click`, `no_safe_point` or `unavailable`.
- Window commands bind Accessibility windows by native window ID before comparing titles. `window inspect`, `window press` and clicks now work on apps such as Chrome, which add their name to the Accessibility title.
- The input helper waits after sending events. A process that exits right after posting loses them.
- Docs, CLI help and the agent skill were checked against the current commands. `doctor` is documented as covering Full Disk Access and Automation only, and X and Threads are documented as social feeds rather than AI conversations.

## Verified

On macOS 27.0.1 with Stage Manager off, background clicks produced exactly one effect in Calculator, TextEdit, Finder, Safari and Chrome. TextEdit also took a background drag selection. During these clicks the foreground app, menu bar and visible Spaces did not change. In a 40-second run on a test window, none of 152 physical key presses reached the target. See the [record](../../dev/computer-use/background-first-click.md).

The `calculation` agent task is the first of eight acceptance tasks to pass in full. See the [run record](../../dev/computer-use/native-agent-tasks.md#recorded-attempts-2026-11-06).

## Compatibility and limits

- `window click` and `window drag` now change behavior: the target app briefly reports itself active, receives its did-become-active notifications, and the clicked window becomes its key window. Each click takes about a quarter of a second longer.
- The 0.6 minor series does not promise source, CLI or JSON compatibility with 0.5.x. Recheck installed help and saved target consumers before upgrading.
- Background drags in web content that reads the held button state are unsupported. WebKit and Chromium read the button state of the whole login session, and events sent to one process do not change it.
- Windows outside the current Stage Manager stage report thumbnail bounds. Clicks on them are unverified.
- Real Electron apps were not tested. Chrome is the nearest coverage.
- Rust 1.88 or newer is required. The CLI remains macOS-only.
- Locked-session operation is not supported. Inactive-Space first save and complete physical-input isolation remain unresolved or unverified.

## Install or upgrade

```sh
cargo install cueward-cli --version 0.6.0 --locked
cueward --help
```

Updating an installed agent skill does not update the executable. Follow the [synchronization guide](../agent-skill.md) separately.
