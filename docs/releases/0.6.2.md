# Cueward 0.6.2

This release fixes background pointer input that could hit the wrong control when Stage Manager is on. The published packages are `cueward-core`, `cueward-adapter-macos` and `cueward-cli`.

## Main changes

- `window click`, `window drag` and `window scroll` now refuse a window outside the current Stage Manager stage. Before this release, a point read from that window's snapshot could land on a different control, and the result still said `sent_unverified`.
- `window input-status` reports the pointer route as not ready for such a window and gives the reason.
- The agent skill now tells agents to use `app inspect` and `app press` for these windows. Both work without changing the stage or the foreground.

The snapshot of a window outside the stage is a tilted thumbnail, and its shape differs from the window, so pixels cannot be mapped to window points. That is why the input is refused rather than converted.

## Verified

Measured on a working desktop with Stage Manager on, three displays, and other agents and builds running. See the [record](../../dev/computer-use/stage-manager.md).

- A click near the bottom of a thumbnail pressed a button near the top of the real window in 3 of 3 runs before the fix. After the fix, click and scroll were refused before any event in 3 of 3 runs.
- `app press` pressed the right button with the stage and foreground unchanged, in 2 of 2 runs after the fix. A third run stopped with `desktop is locked`, because the desktop had auto-locked.
- Three read-only `input-status` sweeps over real windows refused no full-size window as a thumbnail, and refused one real Termdock thumbnail.
- Ten live input and pointer tests passed on the fixed code, including click and drag effects on the stage.
- When an app quit, a window moved or a sheet opened around a command, Cueward stopped or reported what happened. Each of these cases ran once. A click aimed at a sheet button with an old snapshot did not press it in 6 of 6 runs, using one `NSAlert` sheet.

## Compatibility and limits

- The check compares the window's size in the window list with its size through Accessibility. If no matching Accessibility window can be found, it cannot run and behavior is the same as in 0.6.1. This covers Accessibility listing no windows, and a window with no native ID whose title differs or is shared.
- `drag` was covered by tests only. It was not measured on a real window outside the stage.
- A snapshot of some thumbnails fails with `could not create image from window`.
- Real Electron apps have not been tested.
- A disabled first Save panel on an inactive Space is still unsolved.
- Rust 1.88 or newer is required. The CLI remains macOS-only.

## Install or upgrade

```sh
cargo install cueward-cli --version 0.6.2 --locked
cueward --help
```

Updating an installed agent skill does not update the executable. Follow the [synchronization guide](../agent-skill.md) separately.
