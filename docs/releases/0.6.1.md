# Cueward 0.6.1

This release adds on-device Voice Memos transcription and fixes Safari waits across a navigation. The published packages are `cueward-core`, `cueward-adapter-macos` and `cueward-cli`.

## Main changes

- `voice-memos transcribe --id <id> [--locale <locale>]` turns one recording into text on this Mac. See the [Voice Memos guide](../../README.md#voice-memos).
- `safari wait --url` and `safari wait --navigation` no longer fail with `target tab changed` when the page navigates. Every `safari wait` condition now follows its tab while the URL and title change.
- crates.io now lists keywords and categories for `cueward-cli` and `cueward-adapter-macos`, and `cueward-cli` has a current description.
- The agent skill now explains how to read and answer a JavaScript `alert`, `confirm` or `prompt` with `app inspect` and `app press`, without bringing Safari forward. No new command was needed.
- The agent skill covers the new waits, transcription and the 500-node inspection limit.

## Verified

- A 332-second recording produced 805 characters in 4.7 seconds. Six real recordings gave the expected result: two transcripts, two `no speech detected` and two damaged files.
- The wait fix failed before the change and passed three runs after it, in a disposable Safari window.
- In Safari, an `alert`, a `confirm` and a `prompt` were each read and answered in the background. The page received each answer and the foreground did not change. See the [results](../../dev/computer-use/results/2026-11-07-safari-dialogs.json).
- A background `window click` in WKWebView produced `isTrusted: true` events. Safari itself was not measured.
- Cueward 0.6.0 passed text, shortcut, click, canvas drag, scroll and controlled interruption in one idle round on an unchanged receiver. See the [record](../../dev/computer-use/physical-overlap.md#idle-diagnostic-after-click-preparation-2026-11-07). A round with physical typing is still needed.

## Compatibility and limits

- Transcription needs macOS 26 or later and an installed speech locale. Cueward does not download speech assets, and an error names the installed locales.
- Transcripts stored inside an m4a file are not read, because no sample was available to verify a parser.
- The no-speech check was calibrated on synthetic audio. Real background noise that produces confident text is not caught.
- A wait checks the window and the tab position, not the URL and title. If a tab to its left closes during the wait, the index moves and the wait can read another tab. Keep `--js` conditions read-only.
- A window outside the current Stage Manager stage reports thumbnail bounds. One background click on such a Safari window reported `no_safe_point` and had no effect on the page.
- A disabled first Save panel on an inactive Space is still unsolved. Target-only activation does not enable it. See the [record](../../dev/computer-use/first-save-context.md#target-only-activation-2026-11-07).
- Rust 1.88 or newer is required. The CLI remains macOS-only.

## Install or upgrade

```sh
cargo install cueward-cli --version 0.6.1 --locked
cueward --help
```

Updating an installed agent skill does not update the executable. Follow the [synchronization guide](../agent-skill.md) separately.
